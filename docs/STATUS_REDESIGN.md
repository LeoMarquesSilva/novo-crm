## Nota de metodologia — verificação de CSS compilado em rotas dinâmicas

Neste projeto (Next 16 + Turbopack), `.next/static/chunks/*.css` **não contém necessariamente o CSS de componentes usados só em rotas dinâmicas** (quase todas as rotas `/crm/*` são `ƒ Dynamic`, não `○ Static`) — o chunk pode ser gerado por rota, sob demanda. Grep nesses 3 arquivos deu falso-negativo para classes de `crm-notifications-bell.tsx` (ex.: a sombra composta com `var(--primary)`, o seletor `group/item`) mesmo após confirmar que a classe existe no código-fonte. Verificação definitiva: compilar a classe diretamente via `@tailwindcss/postcss` (script Node local, sem depender do bundler do Next) — assim confirma-se que o Tailwind gera CSS válido para a classe, independente de qual chunk do Next acaba recebendo essa regra. Usar esse método (não o grep nos chunks) quando uma classe usada só em componente de rota dinâmica precisar de confirmação.
